`speech-to-text` превращает аудио в текст с помощью [openai-whisper](https://github.com/openai/whisper), обёрнутого в небольшой HTTP-сервис, который вы запускаете сами. Вы отправляете аудиофайл и получаете обратно его транскрипцию. Никакого внешнего API, никакой оплаты за минуты, и ваше аудио никогда не покидает вашу машину.

Проект подходит для локального использования, пакетной транскрипции и запуска собственного STT-сервера в сети.

* **Готовый к работе HTTP-сервер.** Flask под управлением uvicorn загружает Whisper при старте и отвечает на запросы с других машин в вашей локальной сети.
* **Безопасность при параллельных запросах.** Сервер держит пул предварительно загруженных экземпляров Whisper, поэтому несколько запросов транскрибируются параллельно без повторной загрузки модели.
* **CPU или GPU, один и тот же код.** Бэкенд выбирается окружением и тем, какой Docker-образ вы собираете. Видеокарта с CUDA ускоряет инференс, но всё работает и на CPU.
* **В комплекте идёт CLI-клиент.** `stt_client.py` отправляет локальные файлы на сервер и выводит результат.
* **Транскрипция в реальном времени.** Передавайте аудио потоком через WebSocket и получайте каждую фразу по мере того, как она произносится, с привязкой к говорящему, если включена диаризация.
* **В комплекте идёт веб-интерфейс.** Загрузите файл в браузере и прочитайте текст или кто что сказал; интерфейс отдаёт собственный nginx-контейнер рядом с сервером.

### Модели

Whisper поставляется в нескольких размерах моделей. Более крупные модели точнее и медленнее, более мелкие быстрые и лёгкие.

| Модель     | Параметры  | VRAM    | Языки           | Подходит для                                  |
| ---------- | ---------- | ------- | --------------- | --------------------------------------------- |
| `tiny`     | 39M        | ~1 GB   | многоязычная    | быстрые черновики на слабом железе            |
| `base`     | 74M        | ~1 GB   | многоязычная    | лёгкий универсальный вариант по умолчанию     |
| `small`    | 244M       | ~2 GB   | многоязычная    | хороший баланс точности и скорости            |
| `medium`   | 769M       | ~5 GB   | многоязычная    | выше точность, если можно выделить память     |
| `turbo`    | 809M       | ~6 GB   | многоязычная    | точность близкая к `large`, намного быстрее   |
| `large`    | 1550M      | ~10 GB  | многоязычная    | лучшее качество, требуется GPU                |

Англоязычные варианты (`tiny.en`, `base.en`, `small.en`, `medium.en`) чуть точнее на английском аудио. По умолчанию используется `turbo`, лучший универсальный выбор для английского на GPU.

### Быстрый старт (Docker)

Проще всего запустить сервер через Docker. Файлы моделей кешируются в `./models` на хосте, поэтому они переживают пересборку контейнера.

```bash
git clone https://github.com/wachawo/speech-to-text.git
cd speech-to-text

docker compose up --build                              # GPU (CUDA 13.0)
docker compose -f docker-compose-cpu.yml up --build    # CPU only
```

Для сборки под GPU на хосте нужен `nvidia-container-toolkit`. При первом запуске модель Whisper скачивается в `./models`.

### Веб-интерфейс

`docker compose up` также запускает `stt_www`, nginx-контейнер, который отдаёт браузерный интерфейс и пропускает `/api/` на сервер, так что интерфейс и API доступны по одному адресу.

| Протокол | Порт по умолчанию | Задаётся через     |
| -------- | ----------------- | ------------------ |
| http     | `8080`            | `STT_WWW_PORT`     |
| https    | `8443`            | `STT_WWW_TLS_PORT` |

Откройте `http://<host>:8080`. У **TRANSCRIBE** три источника. **FILE** загружает аудиофайл. **DEVICE** транскрибирует в реальном времени со звукового входа: микрофона или гарнитуры, источника `Monitor of ...` в Linux, который несёт всё, что играет через динамики или наушники, или, в браузерах на Chromium, `Tab or screen audio` для того, что играет во вкладке браузера, либо во всей системе, где ОС это позволяет. **STREAM** принимает адрес потока или удалённого файла - интернет-радио, HLS, RTMP, RTSP, SRT - и сервер читает его сам. В любом случае результат появляется под формой обычным текстом или, при включённой диаризации, блоком на каждую фразу с говорящим и временем, где у каждого говорящего свой цвет, а фразы, в которых двое говорили одновременно, помечены; фраза в реальном времени появляется примерно через секунду после того, как говорящий делает паузу. Результат можно скопировать или скачать как TXT или JSON. **MODELS** показывает то, что сообщает `GET /api/models`. Если задана переменная `STT_TOKENS`, интерфейс один раз запрашивает токен и хранит его в браузере.

Браузеры отдают аудиоустройства только защищённой странице, поэтому по сети DEVICE работает через https-порт (и на `http://localhost`). На https-порту используется самоподписанный сертификат, который контейнер создаёт в `./data/certs` при первом запуске; чтобы заменить его, положите туда настоящие `stt.crt` и `stt.key`. У интерфейса нет этапа сборки и нет CDN: Vue 2 и его библиотеки лежат в репозитории в `www/vendor`, поэтому он работает на машине без выхода в интернет.

### HTTP API

Когда сервер запущен, проверьте его статус и отправьте аудиофайл на транскрипцию.

```bash
curl localhost:5099/api/health

curl -X POST localhost:5099/api/stt \
  -F file=@speech.mp3

curl -X POST 'localhost:5099/api/stt?language=ru' \
  -H 'Content-Type: audio/wav' \
  --data-binary @speech.wav
```

`GET /api/health` возвращает статус пула. Падение `available` до 0 означает, что все модели сейчас заняты:

```json
{ "status": "ok", "pool_size": 4, "available": 3, "diarize": false }
```

`POST /api/stt` принимает поле `file` в формате `multipart/form-data` либо сырое тело `audio/*`. Необязательный параметр `language` (в строке запроса или как поле формы) переопределяет язык сервера по умолчанию для конкретного запроса; значение `auto` включает автоопределение. При успехе возвращаются текст и затраченное время в секундах:

```json
{ "text": "transcribed text", "elapsed": 1.23 }
```

Язык можно задать кодом (`ru`) или английским названием (`russian`); всё, чего модель не знает, отклоняется с `400`, а не падает посреди расшифровки. `GET /api/models` перечисляет то, что она знает. Это относится к бэкендам, которые принимают язык (`accepts_language: true`). Parakeet определяет язык сам и игнорирует значение, а неуверенно распознанную речь может молча пропустить: в записи на нескольких языках для языка меньшинства он может не вернуть ничего.

`GET /api/models` сообщает, что умеет этот сервер, чтобы клиенту не приходилось угадывать. Каждый бэкенд приносит свой список языков, потому что наборы действительно расходятся, и объединённый список был бы неверен для каждого бэкенда по отдельности.

```bash
curl -H 'Authorization: Bearer <token>' localhost:5099/api/models
```

```json
{
  "default": "whisper",
  "models": [
    { "backend": "whisper", "model": "turbo", "aliases": ["large-v3-turbo"], "status": "loaded",
      "multilingual": true, "accepts_language": true, "languages_source": "derived",
      "languages": ["en", "zh", "de", "..."], "default_language": "en", "default": true },
    { "backend": "diarize", "model": "nvidia/Nemotron-3-Diarization", "status": "installed",
      "accepts_language": false, "languages": null, "max_speakers": 8, "default": false }
  ]
}
```

`status` равен `loaded`, когда экземпляр ждёт в пуле, `installed`, когда веса лежат на диске, но ничего ещё не загружено, и `absent` в остальных случаях. Бэкенд, который настроен, но не установлен, отвечает `absent` и ничего больше; причина уходит в лог. `accepts_language` говорит, значит ли `?language=` вообще что-нибудь для этого бэкенда. Диаризатор сообщает `null` вместо пустого списка языков, потому что он не производит текст ни на одном языке.

CLI-клиент читает тот же эндпоинт:

```bash
python3 stt_client.py --list
```

`POST /api/diarize` отвечает на вопрос **кто и когда говорил**, и только на него: он возвращает временные интервалы с номером говорящего, но никогда не текст. Эндпоинт выключен, пока не задана переменная `DIARIZE_ENABLED` в образе, собранном с `DIARIZE=true`; иначе он отвечает `503`.

```bash
curl -X POST localhost:5099/api/diarize -F file=@meeting.wav
```

```json
{ "segments": [ { "speaker": 0, "start": 0.51, "end": 12.62 },
                { "speaker": 1, "start": 12.20, "end": 19.04 } ], "speakers": 2, "elapsed": 1.23 }
```

Два замечания об этих числах. Интервалы могут пересекаться, потому что канал каждого говорящего оценивается отдельно, поэтому двое говорящих одновременно дают два интервала, покрывающих одни и те же секунды. И метки это позиции внутри одной этой записи, упорядоченные по тому, кто заговорил первым: это не идентичности, и в следующем запросе тот же человек получит другой номер. Чтобы назвать говорящего по имени, нужен этап регистрации голоса, которого в этом сервисе нет. Различается не более восьми говорящих.

Доступны два бэкенда транскрипции. **Whisper** используется по умолчанию и принимает `language`. **Parakeet** (`nvidia/parakeet-tdt-0.6b-v3`) покрывает 25 европейских языков, определяет язык сам и поэтому не принимает аргумент `language` вовсе, о чём `GET /api/models` сообщает как `accepts_language: false`. Выбирается через `STT_BACKEND=parakeet` в образе, собранном с `PARAKEET=true`; это выбор на этапе развёртывания, а не на каждый запрос, потому что вторая резидентная модель означала бы второй набор весов в каждом рабочем процессе.

Ни один из бэкендов не учитывает перекрывающуюся речь. Модель NVIDIA, учитывающая перекрытие, поставляется только как чекпойнт NeMo, а NeMo требует другую версию PyTorch, чем CUDA-сборка этого проекта, поэтому здесь она неустановима.

`POST /api/transcript` отвечает на вопрос **кто что сказал**: он прогоняет по одному и тому же аудио диаризацию и транскрипцию и соединяет их по времени. Ему нужна включённая диаризация, иначе он отвечает `503`.

```bash
curl -X POST localhost:5099/api/transcript -F file=@meeting.wav
```

```json
{
  "segments": [ { "speaker": 0, "start": 0.5, "end": 4.2, "text": "so where are we", "overlap": false },
                { "speaker": 1, "start": 4.0, "end": 9.8, "text": "green since this morning", "overlap": true } ],
  "turns": [ { "speaker": 0, "start": 0.51, "end": 4.24 }, { "speaker": 1, "start": 4.0, "end": 9.81 } ],
  "speakers": 2,
  "text": "so where are we green since this morning",
  "elapsed": 3.41
}
```

`turns` это сырой вывод диаризатора, а `segments` результат соединения; они держатся порознь, чтобы клиент, не доверяющий привязке, всё равно видел, что сказал диаризатор. `text` это обычная транскрипция, совпадающая с тем, что `/api/stt` возвращает для того же файла. Фраза, которую не покрывает ни один интервал, сохраняет `"speaker": null`, а не отдаётся ближайшему.

`overlap` помечает фразу, во время которой говорил кто-то ещё. NVIDIA прямо указывает, что связка обычной модели на одного говорящего с диаризацией не равнозначна модели, построенной для перекрывающейся речи: извлечённый интервал времени всё равно содержит все голоса, которые его перекрывают, поэтому такие фразы могут смешиваться или брать слова не того говорящего. Считайте сегмент с пометкой `overlap` местом, где транскрипция заслуживает наименьшего доверия.

`/api/stream` это WebSocket для **транскрипции в реальном времени**: аудио поступает по мере записи, а каждая фраза возвращается примерно через секунду после того, как говорящий делает паузу. Управление передаётся текстовыми JSON-сообщениями, аудио передаётся бинарными сообщениями:

1. Клиент отправляет `{"type": "start", "language": "ru", "diarize": true, "token": "<token>"}`. Все поля, кроме `type`, необязательны. Через `token` аутентифицируется браузер, поскольку он не может задавать заголовки у WebSocket; другие клиенты могут вместо этого отправить `Authorization: Bearer <token>` при рукопожатии.
2. Сервер отвечает `{"type": "ready", "sample_rate": 16000, "backend": "whisper", "language": "ru", "diarize": true, "source": "client"}`.
3. Клиент отправляет сырой PCM - знаковый 16-битный little-endian, моно, 16 кГц - бинарными сообщениями любого размера, а по завершении `{"type": "stop"}`.
4. Сервер отправляет `segment` на каждую фразу, `progress` примерно раз в секунду и `done` перед закрытием:

```json
{ "type": "segment", "id": 3, "start": 6.88, "end": 8.2, "text": "This is the second speaker.", "speaker": 1, "overlap": false }
{ "type": "progress", "seconds": 12.3 }
{ "type": "done", "segments": 10, "seconds": 21.87, "elapsed": 22.08 }
```

Аудио может приходить и из другого места. С `"source": "url", "url": "https://..."` в стартовом сообщении клиент вообще не отправляет аудио: сервер читает поток по этому адресу через ffmpeg, пока тот не закончится или клиент не отправит `stop`. Работают интернет-радио, HLS, RTMP, RTSP и SRT; схема должна быть `http`, `https`, `rtmp`, `rtmps`, `rtsp` или `srt`. То, что живой источник уже накопил, забирается сразу, а остальное идёт в собственном темпе источника, так что удалённый файл приходит так же, как пришла бы трансляция.

Поскольку так сервер обращается по адресу, выбранному клиентом, эта возможность ограничена. ffmpeg может использовать только сетевые протоколы, поэтому ни URL, ни плейлист не заставят его прочитать локальный файл, и ничто не может заставить его слушать входящие соединения: режимы SRT `listener` и `rendezvous` и любой параметр `listen` отклоняются. Страница с другого сайта не может запустить такой источник (`Forbidden`): браузеры не применяют CORS к WebSocket, поэтому сокет проверяет, что источник (origin) страницы совпадает с этим хостом или указан в `CORS_ORIGINS`. Одновременно работает не больше четырёх URL-источников (сверх этого `Service Unavailable`), а в лог каждый адрес попадает без учётных данных и строки запроса. Хосты в собственной сети сервера по-прежнему достижимы: для камеры в этом и смысл, и это причина задавать `STT_TOKENS` на сервере, до которого могут дотянуться другие.

Ошибка это одно сообщение `{"type": "error", "error": "<category>", "request_id": "..."}`, за которым следует закрытие; категории те же, что у HTTP-ошибок, плюс `Invalid start message`, `Invalid audio frame`, `Invalid stream URL`, `Stream source failed` и `Forbidden`.

Фраза заканчивается на паузе в 0,6 с, там, где диаризатор слышит, что один говорящий передаёт слово другому (с `diarize`, поскольку люди, отвечающие друг другу, часто оставляют меньше 0,6 с), или, если она длится дольше 15 с, в самом тихом её месте, и транскрибируется отдельно моделью, взятой из того же пула, что и для загрузок, поэтому при занятом пуле фразы в реальном времени задерживаются, а не завершаются ошибкой. С `diarize` диаризатор работает в потоковом режиме и переносит кеш говорящих от фрагмента к фрагменту, поэтому говорящий сохраняет один и тот же номер на всю сессию. Сокет существует, только когда сервер запущен под uvicorn (`python3 stt_server.py`, вариант по умолчанию в Docker): отладочный сервер Flask и рабочие процессы gunicorn типа sync не поддерживают WebSocket.

**Возвращается только произнесённый текст.** Там, где речи нет, будь то тон, музыка, шум, гудки дозвона или даже цифровая тишина, Whisper отвечает титрами субтитрованных видео, на которых он учился ("Продолжение следует...", "Субтитры создавал DimaTorzok", "Thank you for watching."), и делает это с полной уверенностью: на тестовом корпусе его собственный `no_speech_prob` был 0,00 даже на тишине. Поэтому каждый эндпоинт прогоняет по аудио детектор голоса, Silero VAD, и отбрасывает транскрибированный сегмент, который в основном лежит вне обнаруженной речи, а также любой сегмент, целиком состоящий из строки титров. На корпусе из девяти записей без речи это убрало все такие строки и сохранило каждую фразу записей с речью. Запись, в которой ничего не сказано, теперь даёт пустой текст. В потоке в реальном времени фраза без обнаруженной речи даже не отправляется в модель. Детектор работает на CPU и добавляет примерно секунду на каждые три минуты аудио. `SPEECH_GATE=false` возвращает прежнее поведение.

Размер загрузки ограничен значением `MAX_CONTENT_LENGTH_MB` (по умолчанию 10 МБ); большее тело возвращает `413`.

Ошибки единообразны: `error` несёт обобщённую категорию, а `request_id` связывает ответ с записью в логе сервера, где зафиксировано полное исключение.

```json
{ "error": "Invalid audio data", "request_id": "a1b2c3d4e5f6" }
```

Если задана переменная `STT_TOKENS`, каждый запрос, кроме `GET /api/health`, должен содержать `Authorization: Bearer <token>`; сам `GET /api/health` остаётся открытым, чтобы продолжали работать проверки состояния.

### CLI-клиент

`stt_client.py` это небольшой клиент для работы с сервером и его тестирования. Он читает адрес сервера и токен из `STT_URL` и `STT_TOKEN`.

```bash
python3 stt_client.py speech.mp3
python3 stt_client.py file1.wav file2.mp3 file3.ogg
```

`--stream` проигрывает один файл в `/api/stream` со скоростью речи и печатает каждую фразу по мере её возвращения, а `--speakers` добавляет привязку к говорящим:

```bash
python3 stt_client.py --stream meeting.wav --speakers --language ru
```

### Разработка

Должны присутствовать системные пакеты `ffmpeg` и `libsndfile1`. Установите рантайм- и dev-зависимости:

```bash
pip install -e ".[dev]"
pre-commit install
```

Makefile оборачивает типовые задачи:

```bash
make run            # foreground: python3 stt_server.py
make start          # background: PID -> .stt_server.pid, logs -> logs/stt_server.log
make stop           # stop the background server
make gunicorn       # run via gunicorn
make test           # pytest
make lint           # pre-commit (black + ruff)
make typecheck      # mypy
```

Набор тестов подменяет бэкенд Whisper заглушкой, поэтому он покрывает HTTP-слой (request_id, категории ошибок, семантику пула моделей) и выполняется за секунды без скачивания модели и без GPU.
