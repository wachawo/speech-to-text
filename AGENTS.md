# AGENTS.md

Conventions and context for anyone working in this repository, human or tooling.

## What this is

A single-process Flask + uvicorn HTTP service wrapping `openai-whisper` and NVIDIA Parakeet for speech-to-text, with a browser UI in `www/` served by its own nginx container. No database and no worker process of its own - background jobs run on a thread inside each server process - just `stt_server.py` (app wiring, routes, entry point), `stt_client.py` (a CLI that POSTs files to it), `gu.py` (Gunicorn config and hooks) and the `libs/` package holding everything else: `config.py`, `logs.py`, `errors.py`, `auth.py`, `audio.py`, `model_pool.py`, `registry.py`, `catalog.py`, `backends.py`, `stt.py`, `parakeet.py`, `align.py`, `diarize.py`, `speech_gate.py`, `live.py`, `stream.py`, `url_source.py`, `jobs.py`, `longform.py`, `metrics.py`, `openai_api.py`.

## Architecture

- **One module, one job.** `libs/config.py` is the only place `os.getenv` is called and the only place `load_dotenv` runs - enforced, nothing else in the repo calls either. Import it as `from libs import config` and read `config.X` at call time, never `from libs.config import X`: the tests monkeypatch `config` attributes and a copied name would not see the patch. The one exception is `gu.py`, which imports it as `stt_config`: gunicorn treats every module-level name in its config file that matches a setting as that setting, and `config` is one.
- **Model pools, not a model singleton.** `libs/model_pool.py::init_model_pool()` first runs `registry.validate_model_specs()`, then pre-loads every model's instances into its own `queue.Queue` in `MODEL_POOLS`, keyed by the model's canonical id; `MODELS_LOADED` counts what was created, so a model whose every instance is busy still reads as loaded. Each `/api/stt` request resolves its model, calls `acquire_model(model_id=...)`, runs the backend's `get_stt_result()`, and `release_model(instance, model_id=...)`s it in `finally`, always back into the pool it came from. Pool exhaustion returns 503. This is what makes the server safe under concurrency, because no transcriber is thread-safe.
- **The registry decides what a request may select.** `libs/registry.py` turns `STT_MODELS` (or, when it is empty, the single model `STT_BACKEND` / `WHISPER_MODEL` / `PARAKEET_MODEL` imply) into specs `{id, backend, model, pool_size}`, recomputed on every call so a monkeypatched `config` is obeyed. It imports `config` and `backends` and never `model_pool`, which imports it. A file-path entry is served under its basename without `.pt`: the path stays in `spec["model"]` and never reaches a client. Everything derived from a name (a Whisper language list, `multilingual`) is derived from that id through `config.build_model_name`, never from the path: `/models/tiny.en.pt` is tiny.en. A name that matches no known checkpoint gets a list that is only a guess, so a request without `model` has its code passed on rather than refused on that guess (`backends.is_unlisted_language_forgiven`). `STT_DEFAULT_MODEL` also accepts a path entry exactly as `STT_MODELS` spells it; a request's `model` never matches a path. Two entries one name would select, or an entry served under a backend name, stop startup.
- **Each backend describes itself.** `libs/catalog.py` assembles `GET /api/models` from a `describe_backend()` in each backend module, then upgrades `status` to `loaded` by looking at the pools. The catalogue must keep working when a backend cannot describe itself, so the failure is logged and that row is skipped. `libs/catalog.py` must never import `whisper` or `transformers` directly: CI installs only `.[dev]`, which has neither, and the backend modules are what the tests replace.
- **Whisper's language list is derived from the checkpoint NAME, not by loading it.** The large-v3 lineage knows 100 codes, every other multilingual checkpoint the first 99, a `.en` checkpoint one. And the name is not the filename: `turbo` downloads as `large-v3-turbo.pt`, so an installed check that compares the configured name against the directory listing reports a running model as missing. Resolve through `whisper._MODELS`.
- **Several models, chosen per request among pre-loaded ones; never lazily loaded.** A request names a model with `model` (id, alias, `backend:model` or a bare backend) and gets one of the models loaded at startup, or a 400 (`Invalid model` for a name no backend knows, `Model not loaded` for a real one this server did not load). Loading on demand would stall a request for minutes and grow memory without bound, so it does not exist. Memory is workers times the sum of `pool x model size`; under Gunicorn each sync worker serves one request at a time, so `@1` per entry is the sane choice there.
- **Every transcriber module has the same surface.** `libs/backends.py` maps a backend name to a module (`transcriber_for_backend(name)`; the single-model path reaches it through `registry.build_legacy_spec()`), and every transcriber module exports the same names with the same signatures: `get_model(device, model_name)`, `get_stt_result`, `get_stt_bio`, `get_stt_segments`, `describe_backend(model_name)`, `resolve_languages`, `list_aliases`, `list_known_models`. `get_stt_result` returns `{text, language, segments}` from one decode - in `libs/stt.py` the single `decode_buffer` call that `get_stt_bio` and `get_stt_segments` go through as well - so a caller that needs the text and the segments never runs the model twice. `WORD_SEGMENTS` is an optional module attribute: a module that sets it returns words from `get_stt_segments`, not phrases. Callers resolve the **module** and then call it by name - `backends.transcriber_for_backend(spec["backend"]).get_stt_result(...)`. A dispatcher that resolved the function instead would leave the tests patching `stt.get_stt_result` intercepting nothing, and they would keep passing while testing nothing. **Tests of the `/api/stt` route patch `get_stt_result`, not `get_stt_bio`**: the route no longer calls the latter, so patching it tests nothing. An unknown `STT_BACKEND` logs once and falls back rather than failing to start; an unknown backend in `STT_MODELS` stops startup.
- **Parakeet takes no language.** It detects it, so `normalize_language_code` deliberately does not exist on that module, and the backend never receives a hint it would honour. A request without `model` keeps the old path: `backends.resolve_language` accepts any value and ignores it rather than checking it against a foreign table. A request that names its model is checked against that model's own list (`Unsupported language` outside it; an id the table does not cover accepts anything). The catalogue says `accepts_language: false`. Its 25 language codes are in no config file the runtime can read, so they are a constant in `libs/parakeet.py` carrying the date and the model id they were read for, and an id outside that table reports `null` rather than a guess.
- **The join merges runs only when nobody else spoke in between.** Two segments of one speaker with another speaker's diarized turn in the gap stay separate, even when the transcriber produced no words for that turn - otherwise the output claims one person talked through the other. Parakeet feeds the join **words**, not phrases: a silence threshold long enough to keep one person's sentence together is longer than a normal handover. It says so with `WORD_SEGMENTS = True`, and the live stream then runs the same join over each utterance's words before sending them (`libs/stream.py::attribute_live_segments`, which reads `WORD_SEGMENTS` from the module of the session's model), so a phrase does not arrive as one segment per word; Whisper's live segments are phrases already and go out one by one.
- **Parakeet can drop speech silently.** It detects the language once per file, and on the deployment host it produced no tokens at all for an English voice inside a Russian recording - about half the English in a three-minute mixed meeting - and also skipped fragments of the main language it was unsure of. The response is a 200 with no sign anything was lost. A mixed-language conversation may lose its minority language under this backend; Whisper with an explicit `language` does not have this failure mode.
- **Nothing installable here solves overlapping speech.** The join in `libs/align.py` attributes each transcription segment to the speaker turn it overlaps most, and NVIDIA states plainly that this is not equivalent to a model built for overlap: the range still contains every voice inside it. The overlap-aware model, Multitalker Parakeet, ships only as a NeMo checkpoint and NeMo is ruled out by the torch pin. Say this rather than approximating it.
- **Whisper's own confidence cannot catch its hallucinations; a voice detector does.** On tone, music, noise, ringback and even digital silence Whisper returns subtitle credits (a Russian "subtitles by DimaTorzok" line, "to be continued...") with `no_speech_prob` 0.00 and the best log-probabilities of the run, so thresholds on those numbers remove nothing. `libs/speech_gate.py` runs Silero VAD (threshold 0.35, 100 ms minimum speech - tuned on a corpus so that no segment of real speech fell under the 0.3 share) and drops segments mostly outside speech, plus whole-segment credit lines no person says, which covers music with vocals. A backend whose segments are words (`WORD_SEGMENTS`, Parakeet) is judged by distance instead: a word is kept when it overlaps a speech range or lies within `WORD_SPEECH_MARGIN` (0.3 s) of one. The share was meant for multi-second phrases; on a word of a quarter of a second the detector's onset lag (Parakeet's first word started anywhere from 0.28 s before the range to 0.04 s after it) and its 0.1 s rounding of range edges are as long as the word, and it dropped the first word of 14 of 40 LibriSpeech phrases (Parakeet WER 6.1% gated, 1.1% ungated). The margin comes from distances: the farthest real word lay 0.08 s from a range on clean phrases and 0.22 s in noise, plus one 80 ms Parakeet frame. Every gate call site passes the flag, read from the module as `stream.attribute_live_segments` reads it, and Whisper keeps the share check unchanged. Parakeet does hallucinate on quiet room tone (a Spanish line on low brown noise), but those words lie far from any speech range - infinitely far when the detector finds none - so the word rule drops them as the share did; in the measured mixes of speech and non-speech it produced no words in the non-speech parts. A detector that cannot be imported or loaded is logged once and leaves the gate off for the process; any other failure is logged and leaves only that request unfiltered. Tests run with `SPEECH_GATE` off (autouse fixture) because CI has no silero-vad; the gate's own tests replace `detect_speech`. The detector is imported inside functions: it pulls in torch, which must not load before `fork()`.
- **With diarization, a live phrase is also cut at a speaker change.** `libs/live.py::split_at_handover` runs whenever a phrase is open and another diarizer step of audio has arrived (`processor.num_mel_frames_per_step`, about 0.72 s; the first chunk about 1.04 s), and after each idle catch-up. `advance_stream` leaves `ready_at`, the sample count the next chunk needs, so the worker decides without borrowing a diarizer; it then borrows one for that step only and releases it before any phrase is transcribed. It asks `diarize.find_handover` for the first turn of another speaker that has lasted 0.4 s while the phrase's speaker was silent; overlap is not a handover and stays one phrase with `overlap` set. The phrase's speaker is whoever talks most in its first 0.5 s, not whoever's turn begins first: a phrase opened by such a cut starts where the new speaker does, yet the previous speaker's last frame can still land inside it - `stream_turns` rounds the first frame down, or the voice trails past the cut - and that turn would begin first or win the tie on the lower label, hiding every later handover in that phrase. The new speaker is guaranteed the larger share only while `HANDOVER_MIN_OFFSET` stays at or above `HANDOVER_SECONDS` and under 1.75 times it.
- **`word_timestamps=True` is not used and must not be added casually.** It rewrites `seek` from the end of the last word and clears zero-length segments whose tokens then never reach the text, so it can change the transcription the decoding settings fix on purpose. Segment times come free from the same unmodified call.
- **Diarization is a second model, and it produces no text.** `libs/diarize.py` wraps `nvidia/Nemotron-3-Diarization`, which emits a `[T, 8]` per-frame activity tensor that becomes `{speaker, start, end}` turns. Whisper is what produces words; pairing the two is what would produce a speaker-attributed transcript. Turns may overlap (each speaker channel is scored independently) and the labels are arrival-order positions in one recording, never identities, so nothing may present them as named people. Eight speakers is the ceiling.
- **Separate pools, not one queue with several kinds.** Every transcription model has its own queue in `MODEL_POOLS`, and `DIARIZER_POOL` is another, all in `libs/model_pool.py`. A queue hands out whatever is at its head and has no notion of kind, so mixing them would make every caller check what it got. `WAITING`, the count of callers blocked in `acquire_*`, is kept per pool as well (`model:<id>` from `build_waiting_kind`, and `diarizer`), so background work steps aside only for callers of the pool it borrows from. `init_diarizer_pool()` is a no-op unless `DIARIZE_ENABLED`, and every pool fills inside the one `flock` in `gu.py::post_fork` because every model downloads on first run.
- **The diarizer needs transformers 5.18.0 or later.** The model declares `transformers_version 5.18.0.dev0`; 5.17.0 answers `AutoConfig` with "model type `nemotron3_diarization` but Transformers does not recognize this architecture", and the repository ships no custom modeling code, so `trust_remote_code` is not a way around it. Until 5.18.0 shipped the pin was a git commit. Now `requirements-diarize.txt`, `requirements-parakeet.txt` and both extras share the floor `>=5.18.0`, so the two backends install together, and the images hold the exact version through `constraints.txt`.
- **The GPU image asserts its own torch.** `Dockerfile` installs a `+cu130` wheel and then runs further unconstrained resolutions; anything depending on torch can replace it, and the failure surfaces much later as cuBLAS and cuDNN errors that read like a driver problem. A `RUN python3 -c "assert '+cu130' in torch.__version__"` turns that into a build failure. Do not remove it, and add the same shape of check for any new pin that matters. The same Dockerfile checks torch's compiled arch flags for GB10 (`sm_120` or its `compute_120` PTX; the build has no `sm_121`), read from `torch._C._cuda_getArchFlags()` because `get_arch_list()` is empty without a GPU at build time. Every install step runs with `-c constraints.txt`, the versions of the last verified image; regenerate it with `make constraints` after a dependency change is built and checked, and leave torch and the CUDA wheels out of it. The uv image is pinned (`uv:0.12.19`): a moving `latest` threw away every later layer's cache.
- **Three run modes, two pool semantics:**
  - **Direct (`python3 stt_server.py`)** - one process; the pools live in it and each model's pool size is its real concurrency limit. uvicorn keeps an idle connection open for `STT_KEEPALIVE_SECONDS` (`timeout_keep_alive`), so a client sending phrase after phrase does not pay a new connection each time.
  - **Gunicorn (`gunicorn --config gu.py stt_server:app`)** - `worker_class = "sync"`, `GUNICORN_WORKERS` processes; each worker calls `init_model_pool` from `post_fork` under an `flock` on `/tmp/.stt_model_init.lock` so only one downloads the models. With sync workers `STT_POOL_SIZE=1` (or `@1` on every `STT_MODELS` entry) per worker is intentional - concurrency comes from worker count. A model list that cannot be served fails the worker boot, and gunicorn stops with "Worker failed to boot" rather than looping; a syntax error in `STT_MODELS` already fails the master when it imports `libs/config.py`. **Do not switch to `gthread`**: PyTorch's MKL/OpenBLAS thread pools deadlock with Gunicorn threads. Sync workers close the connection after every response and ignore `keepalive`.
  - **Gunicorn with the live stream (`gunicorn --config gu.py stt_server:asgi_app`, `GUNICORN_WORKER_CLASS=uvicorn_worker.UvicornWorker`)** - the same per-worker pools, plus `/api/stream`, which a sync worker cannot hold open. It runs Flask in a thread pool exactly as `python3 stt_server.py` always has, so the `gthread` warning above does not carry over; `gu.py` sets gunicorn's `keepalive` from `STT_KEEPALIVE_SECONDS`, which this worker reads as its keep-alive timeout; measured on the deployment GPU with two workers, four live streams, six concurrent 200 s uploads and scrapes: everything completed, no worker timed out or restarted.
- **A synchronous request waits `STT_QUEUE_TIMEOUT` for its model.** `/api/stt`, `/api/transcript` and any future route that answers a transcription in its own response borrow through `model_pool.acquire_request_model`, which waits that long (default 120 s, a float, so a server that answers short phrases can say 0.3) before the 503. Background work keeps `MODEL_ACQUIRE_TIMEOUT` - job pieces and live phrases both go through `libs/stream.py::transcribe_piece` - and the diarizer keeps `DIARIZER_ACQUIRE_TIMEOUT`. A request waiting there is counted in `WAITING` like any other caller, so `yield_to_waiters` still makes a job step aside for it.
- **No audio and no transcript in the log or on disk on the synchronous path.** `/api/stt`, `/api/transcript`, `/api/diarize` and `/v1/audio/transcriptions` keep the upload, the converted WAV and the text in memory - werkzeug's multipart parser, which spools a file part over 500 KB to a temporary file, is replaced by `stt_server.py::MemoryFormDataParser` on every route but `POST /api/jobs`, which spools its file part under `JOBS_DIR` instead (`stt_server.py::JobFormDataParser`) so a recording of a gigabyte never lands in the tmpfs at `/tmp`, and a 16 kHz mono 16-bit PCM WAV is passed on without any decoding. One exception remains: an upload that pydub has to decode reaches ffmpeg and ffprobe as `cache:pipe:0`, and that protocol copies the input into an unlinked temporary file under `TMPDIR` for the length of the decode. Only a tmpfs at `/tmp` keeps that in memory, which is why both compose files mount one there for `stt_server`. A log line may carry ids, sizes, counts, shares, durations, model ids and language codes, never the words, the samples or a request's `prompt`: the speech gate logs a dropped segment's speech share and its length, not its text. The client's filename is logged as a label. Background jobs store their upload under `JOBS_DIR` by design, until the job has run, and their result until `JOB_RETENTION_HOURS`. The `python3 -m libs.stt` and `python3 -m libs.parakeet` CLIs print the transcript because that is their output.
- **Torch must never load before `fork()`.** `libs/stt.py`, and therefore `libs/backends.py`, `libs/registry.py` and `libs/model_pool.py`, pulls in torch and whisper. `gu.py` imports `init_model_pool` inside `post_fork`, not at module scope. The tests rely on the same boundary - `tests/conftest.py` replaces `sys.modules["libs.stt"]` with a stub before importing `stt_server`, so the suite needs neither torch nor whisper.
- **Audio path.** `libs/audio.py::convert_to_wav()` hands every synchronous upload on as 16 kHz mono 16-bit WAV in a `BytesIO` before `get_stt_result()` sees it. An upload that already is exactly that - RIFF/WAVE, format tag 1 (PCM), one channel, 16000 Hz, 16 bits - is passed on untouched (`is_target_wav` walks the chunk headers only, skipping LIST and any other chunk with its pad byte, and accepts a fmt chunk longer than 16 bytes); everything else, WAVE_FORMAT_EXTENSIBLE included, is decoded through pydub and exported as before. The pass-through saved 70 ms per short phrase, and it adds no resampling anywhere. Every reader downstream (`libs/stt.py`, `libs/parakeet.py`, `libs/diarize.py`, the speech gate) decodes with soundfile, which takes a recorder's extra chunks exactly as it takes pydub's plain 44-byte header (a data chunk declaring 0 bytes, left by a writer that could not seek back, is the exception: soundfile reads it as empty and ffmpeg reads to the end, so it takes pydub), so a reader that parses the header itself, or assumes the data starts at byte 44, breaks this contract. The server does the resampling so `libs/stt.py` skips its torchaudio resample branch on the hot path. Changing one side means keeping this contract intact.
- **Determinism is deliberate.** `libs/stt.py::decode_buffer` is the one seeded decode behind `get_stt_result`, `get_stt_bio` and `get_stt_segments`: it seeds torch + numpy and decodes with `temperature=0.0, beam_size=WHISPER_BEAM_SIZE, best_of=1, fp16=WHISPER_FP16, condition_on_previous_text=False`. The beam size is a setting (default 1, the greedy decode every deployment had before it existed); a wider beam searches more hypotheses at temperature 0 and still picks among them deterministically, so the output stays the same for repeated identical inputs. Don't relax the rest without a reason - the goal is stable output for repeated identical inputs.
- **CPU vs GPU is environment-only.** The same Python code runs both; `COMPUTE_TYPE` (`cpu` / `cuda` / `auto`) plus the chosen Dockerfile/compose file select the backend. `Dockerfile` + `docker-compose.yml` (CUDA 13.0, `torch+cu130`) and `Dockerfile-cpu` + `docker-compose-cpu.yml` are the two images. A Pascal card such as the Tesla P40 (sm_61) runs the same `Dockerfile` and `docker-compose.yml` with a different CUDA build: CUDA 13 and the cu128/cu130 torch builds dropped sm_50-sm_61, and the cu126 build still carries sm_60 kernels, which run on sm_61. Five build args select the build and go together: `CUDA_IMAGE`, `CUBLAS_PACKAGE`, `TORCH_VERSION`, `TORCH_CUDA` and `TORCH_ARCHES` (the kernels the build must carry, any one of them). `docker-compose.yml` passes them from `.env` as `"${NAME:-default}"`, with the main image as the default, and that default must stay equal to the `ARG` default in the `Dockerfile`: compose passes every arg it lists, and an empty one would replace the Dockerfile's default with an empty string. A Pascal host sets the five in its `.env` together with `WHISPER_FP16=false`, because Pascal runs fp16 at 1/64 of the fp32 rate (the commented block in `.env.example`). The torch and arch assertions read the same args.
- **One compose file per image, the same names on every host, every difference in `.env`.** The server container is always `stt_server` and the web UI `stt_www`, whatever the host; a host that differs - its GPU generation, ports, pool sizes, models, time zone - says so in its `.env`, never in a second compose file, an override file or a renamed container or image. A value in a compose `environment:` block overrides `env_file:`, so a literal there is a setting `.env` cannot change: anything a host may tune is written `"${NAME:-default}"`, and a literal stays only where the image or a bind mount fixes it, with a comment saying so - `STT_HOST` (the container must listen on every interface), the three `*_DOWNLOAD_ROOT` (`/opt/models`, the mount `entrypoint.sh` chowns), `JOBS_DIR` (under the mounted `recs/`), `COMPUTE_TYPE` and the `NVIDIA_*` hints (the file is the GPU or the CPU variant by definition) and `DIARIZE_ENABLED=false` in the CPU file, whose image has no diarizer. Keys that need no compose default at all (`DIARIZE_ENABLED` in the GPU file, `STT_MODELS`, `STT_DEFAULT_MODEL`, `WHISPER_FP16`) are not listed and come from `.env` through `env_file:`. Interpolation reads the shell environment before `.env`, so a variable exported in the deploying shell wins over the file.
- **The web UI is static files behind nginx.** `stt_www` (`Dockerfile-www`, `nginx/`) serves `www/` and proxies `/api/` to `stt_server`, so the browser and the API share one origin and CORS never comes into it. It follows the sibling text-to-speech project's UI file for file - vendored libraries under `www/vendor` and no CDN, `.vue` screens loaded by httpVueLoader, the same palette and shell - and the two should keep looking alike. `www/` is bind-mounted, so a UI change needs a browser reload, not a rebuild. The UI learns whether a token is needed from a `401` on `GET /api/models`: health is open and says nothing about auth. The transcribe screen's model select lists the catalogue rows with `selectable: true` and sends nothing for the default; FILE, DEVICE and STREAM send the chosen model, and Turns, which transcribes nothing, sends none. It appears only with two such rows or more, so a server with one model, or one from before per-request models that has no such rows, shows no select and gets the requests it always got.
- **One ASGI app, dispatched by path.** `stt_server.build_asgi_app()` sends the `/api/stream` websocket to `libs/live.py` and everything else to Flask through uvicorn's WSGI middleware. Dispatched, not mounted: mounting strips the prefix, and Flask would then answer its own 404 for `/health`. The socket exists only under uvicorn; gunicorn's sync workers and the Flask debug server serve Flask alone.
- **A live session borrows models per phrase.** `libs/stream.py` cuts phrases at pauses with an energy detector and transcribes each one with an instance taken from the session's model pool (`MODEL_POOLS[spec["id"]]`, the model the start message chose or the default) for that phrase only, so a stream waits for uploads instead of starving them. The diarizer runs in its streaming mode (`libs/diarize.py::advance_stream`, the model card's loop) with the model's speaker cache kept in the session, which is what keeps speaker numbers stable for hours; it too borrows from its pool per call. Blocking calls go through `asyncio.to_thread`, and the event loop only moves audio.
- **A long silence must not grow the buffer.** With nothing to transcribe for a second, the worker catches the diarizer up and trims every sample nothing needs any more (`libs/live.py::find_keep_from`). Without it a quiet hour keeps an hour of audio in memory and leaves the diarizer an hour behind when speech resumes.
- **A URL source makes the server fetch what a client names.** `libs/url_source.py` owns it, and every rule there leans towards refusing. One normalised string is both what is checked and what ffmpeg runs (urlsplit silently drops tabs and newlines ffmpeg would keep, so checking a cleaned copy is how a URL passes and then does something else). ffmpeg gets `-protocol_whitelist` with network protocols only, because a playlist fetched over http can point at `file:` or `concat:`; nothing may make it listen (SRT listener/rendezvous, `listen`); the host may not be or resolve to a loopback, link-local (169.254.169.254, the cloud metadata address) or unspecified address, IPv4 wrapped in IPv6 included, while private LAN ranges (RFC 1918, ULA) stay allowed on purpose, because cameras and encoders on the local network are the main use - and that is a check at start only, since ffmpeg resolves the name again and follows HTTP redirects and playlists, so it narrows the door rather than closes it; an IP literal is judged in `normalize_url`, but a name is resolved only in `handle_stream`, after the origin check and with a session slot held, in a thread: a lookup blocks for as long as the resolver takes, and done earlier it let a cross-site page make the server resolve names and learn the answer, and let a burst of starts tie up the executor live sessions transcribe on; a browser page may start one only from this host's origin, since browsers apply no CORS to websockets - Origin and Host are both the attacker's under DNS rebinding, so this stops nothing without `STT_TOKENS`, and a server that browsers visiting untrusted sites can reach should set it; at most `MAX_URL_SESSIONS` run at once in each worker process, so `GUNICORN_WORKERS` times that for the server; the log gets the address without credentials or query. RTSP takes `-timeout`, every other scheme `-rw_timeout`: ffmpeg aborts on an input option nobody consumed. stderr is drained while ffmpeg runs - read after exit, a noisy source fills the pipe and freezes the session. `-readrate 1` with an initial burst, never `-re`, which paces a live source's backlog into permanent lag. ffmpeg is killed when the session ends, whichever way it ends.
- **Browser capture runs at the device's own rate and downsamples itself.** `www/js/capture.js` opens the device (echo cancellation and noise suppression off: they damage a loopback or a second voice) or `getDisplayMedia` for tab or system sound, and an AudioWorklet averages it down to 16 kHz mono PCM16 in 100 ms frames. An AudioContext created at 16 kHz would be simpler, and Firefox refuses to connect a stream of another rate into it. Devices exist only on a secure page, which is what the https listener of `stt_www` is for.
- **A long recording is a job, processed in pieces that give the model back.** `libs/jobs.py` stores each job as files under `JOBS_DIR` and a worker thread per process claims the oldest with a non-blocking `flock` on its `job.lock`, so gunicorn workers never run one twice and a job whose process died is claimed again - at most `MAX_ATTEMPTS` (3) claims in all, and a restart mid-job counts as one, since nothing hands a running job back on shutdown. `libs/longform.py` cuts the audio every ~60 s at a pause and borrows the model per piece through `libs/stream.py::transcribe_piece`, the same function a live utterance goes through, so the two cannot drift apart; diarization is the streaming mode over the whole file, 60 s per borrow. `queue.Queue` is not fair - a thread that puts an instance back and asks again gets it before a waiting thread wakes - so after every release the job calls `model_pool.yield_to_waiters()` with the kind of the pool it borrowed from (`build_waiting_kind` of its model, or `diarizer`), which waits while `WAITING[kind]` says somebody is blocked in `acquire_*` on that pool; a caller of another model waits on another queue and is not counted. Without that, and with five-minute pieces, a phone call's request waited 205 s behind a job; with it, 10 s at worst. A transcribing job keeps the model it was accepted for: `stt_server.py::resolve_job_options` resolves `model` and the language at submit, the record stores the model's id, and `libs/jobs.py::run_job` resolves that id again when it claims the job and fails it as `Model not loaded` if a restart unloaded it, rather than run it on a model its language was never checked against. A `turns` job, like `/api/diarize`, reads no `model` and only checks that its language is one.
- **The voice detector takes its lock per 30 s window.** Silero keeps recurrent state, so one lock serialises it; held for a whole hour of audio it blocked every short request's gate for minutes (198 s measured). `detect_speech` runs the audio in `VAD_WINDOW_SECONDS` windows and merges ranges that touch across an edge. Keep `OMP_NUM_THREADS=1`: with torch's default thread count the detector ran eight times slower on the GB10 host, and four threads were slower than one.
- **Containers start as root, then drop.** `entrypoint.sh` runs as root, chowns the bind-mounted `/opt/models`, `/opt/logs`, `/opt/recs` (host-owned mounts the build-time chown cannot reach) and `exec`s the command via `setpriv` as `STT_UID`:`STT_GID` when set - the host user, so those directories stay writable to them - and as the image's `stt` user otherwise. Such a uid owns nothing in the image and its `$HOME` is `/root`, which is why the Dockerfiles point `NUMBA_CACHE_DIR` and `XDG_CACHE_HOME` at `/tmp`: numba, under librosa, refuses to import without a writable cache, and that took the diarizer down on the first try. Without it the first `whisper.load_model` dies with `PermissionError`.
- **The GPU is requested through CDI** (`devices: [nvidia.com/gpu=all]`), not `deploy.resources.reservations.devices`: with the latter a `systemctl daemon-reload` silently revokes device access on cgroup v2, and the failure surfaces as misleading cuDNN/cuBLAS errors. CDI needs `sudo nvidia-ctk cdi generate --output=/etc/cdi/nvidia.yaml` on the host, regenerated after driver updates.

## Commands

```bash
make run           # foreground: python3 stt_server.py
make start         # background via nohup; PID -> .stt_server.pid, logs -> logs/stt_server.log
make stop          # kills the PID from .stt_server.pid (SIGTERM, then SIGKILL after 1s)
make gunicorn      # gunicorn --config gu.py stt_server:app

make test          # pytest with coverage (stubs Whisper; no model download, no GPU)
make lint          # pre-commit: black + ruff over the whole repo
make typecheck     # mypy
make constraints   # freeze the verified GPU image's dependency versions into constraints.txt
make tag-rollback  # tag both running images as rollback-<rev> before a deploy

docker compose up --build                            # GPU build (default; a Pascal host sets the CUDA build args in .env)
docker compose -f docker-compose-cpu.yml up --build   # CPU build

python3 stt_client.py [--model NAME] [--language CODE] file.mp3 [file2 ...]   # respects STT_URL (default http://localhost:5051)
python3 stt_client.py --stream file.wav --speakers   # play a file into /api/stream in real time
python3 -m libs.stt file.wav                 # transcribe one file without the server
python3 -m libs.diarize file.wav             # speaker turns for one 16 kHz mono file

DIARIZE=true docker compose up --build       # GPU image WITH the diarization backend
```

Dev install is `pip install -e ".[dev]"`, which is also what CI runs. CI has three jobs: **lint** (`pre-commit run --all-files`, `mypy`, and `node --check` on `www/js/*.js` and on the `<script>` block of every `www/views/*.vue`), **test** (`pytest`) and **images** (builds the CPU and web UI images, imports the server inside the CPU one, runs `nginx -t` on the rendered config). All must pass before a PR is mergeable. The GPU image is not built in CI - its CUDA layers do not fit on a hosted runner - so changing `Dockerfile` or `entrypoint.sh` still needs a build on a GPU host. A tag of the form `1.2.3` triggers **release**, which builds the wheel and sdist, cuts a GitHub Release from the matching `### [1.2.3]` section of `CHANGELOG.md` - so that section must exist before the tag is pushed - and pushes the CPU and web UI images to GHCR as `speech-to-text-cpu` and `speech-to-text-www`.

The project is an installable package. `pip install speech-to-text` gives the HTTP layer, the error handling and the CLI client; the transcription backend is the `whisper` extra, because `openai-whisper` pulls torch and that is the wrong default for someone who only wants to talk to a server. `requirements.txt` is the server's install, which does include the backend, and is what the Docker images use. Entry points: `stt-server` and `stt-client`.

## Environment

`.env` is loaded once, by `libs/config.py`. Variables actually consumed by the code:

- Server: `STT_HOST`, `STT_PORT`, `STT_POOL_SIZE` (instances per model; the default for an `STT_MODELS` entry without `@pool`, 8 outside Docker), `STT_QUEUE_TIMEOUT` (seconds a synchronous request waits for an instance of its model before 503, default 120), `STT_KEEPALIVE_SECONDS` (idle keep-alive of a connection, default 5), `STT_DEBUG`, `LOG_LEVEL`, `LOG_ACCESS`
- Auth / limits / CORS: `STT_TOKENS` (comma-separated; empty disables auth), `MAX_CONTENT_LENGTH_MB`, `CORS_ORIGINS`
- Whisper: `WHISPER_MODEL`, `WHISPER_LANGUAGE`, `WHISPER_DOWNLOAD_ROOT` (host `models`, container `/opt/models`), `COMPUTE_TYPE`, `WHISPER_BEAM_SIZE` (an integer of 1 or more, default 1), `WHISPER_FP16` (half precision on CUDA, default true; false on a Pascal host's `.env`)
- Transcription backend: `STT_BACKEND` (`whisper` or `parakeet`), `PARAKEET_MODEL`, `PARAKEET_DOWNLOAD_ROOT`. Parakeet only exists in an image built with `--build-arg PARAKEET=true`.
- Several models: `STT_MODELS` (comma-separated `backend:model[@pool]`; empty keeps the single model above, set it and `STT_BACKEND` / `WHISPER_MODEL` / `PARAKEET_MODEL` no longer choose what loads) and `STT_DEFAULT_MODEL` (the model a request without `model` gets, by any name a request may use or, for a path entry, the path as written; empty means the first entry). `WHISPER_LANGUAGE` stays the default for every Whisper model. Like `DIARIZE_ENABLED`, never pin either in a compose `environment:` block.
- Jobs: `JOBS_DIR` (Docker `/opt/recs/jobs`), `JOB_MAX_CONTENT_LENGTH_MB`, `JOB_RETENTION_HOURS`
- Speech gate: `SPEECH_GATE` (default true; needs silero-vad, which the `whisper` extra and `requirements.txt` bring)
- Diarization: `DIARIZE_ENABLED`, `DIARIZE_MODEL`, `DIARIZE_POOL_SIZE`, `DIARIZE_DOWNLOAD_ROOT`, `DIARIZE_THRESHOLD`. Two knobs, deliberately separate: `DIARIZE` is a compose **build** arg deciding whether the backend is installed at all, `DIARIZE_ENABLED` is the **runtime** switch. Never pin `DIARIZE_ENABLED` in a compose `environment:` block, which overrides `env_file:` and would silently ignore `.env`. The compose files once pinned `STT_POOL_SIZE: "1"` and fell into exactly this trap - a host whose `.env` said 2 ran a pool of 1 - so a value that `.env` should be able to change is written there as `"${NAME:-default}"`, never as a literal.
- Gunicorn: `GUNICORN_WORKERS`, `GUNICORN_WORKER_CLASS` (`sync`, or `uvicorn_worker.UvicornWorker` for the live stream)
- Client: `STT_URL`, `STT_TOKEN`
- GPU image build (compose only, read at build time from `.env` like `DIARIZE` and `PARAKEET`, never by the Python code): `CUDA_IMAGE` (default `nvidia/cuda:13.0.3-cudnn-runtime-ubuntu24.04`), `CUBLAS_PACKAGE` (`libcublas-13-0`), `TORCH_VERSION` (`2.10.0`), `TORCH_CUDA` (`cu130`) and `TORCH_ARCHES` (`sm_121 sm_120 compute_120`). Unset, they build the main image; a Pascal host sets all five (`nvidia/cuda:12.6.3-cudnn-runtime-ubuntu24.04`, `libcublas-12-6`, `2.9.0`, `cu126`, `sm_61 sm_60`).
- Web UI (compose only, never read by the Python code): `STT_WWW_PORT` (one port, default 5053) and `STT_WWW_SCHEME` (`https`, the default, or `http`; `nginx/25-listen-scheme.sh` writes the listener and refuses any other value)
- Container (read by `entrypoint.sh`, Hugging Face, torch or the C library, not by `libs/config.py`): `STT_UID`, `STT_GID`, `HF_HUB_OFFLINE`, and through the compose files `TZ` (default `America/New_York`), `OMP_NUM_THREADS` and `MKL_NUM_THREADS` (default 1)

Model `.pt` files live in `./models/` and are mounted at `/opt/models`, so the cache survives rebuilds.

## Endpoints

- `GET /metrics` - Prometheus metrics; open like health, not proxied by `stt_www`. Route labels come from Flask's `url_rule`, never the raw path, so 404 probes cannot grow the series. The scrape-time gauges are a `Collector` subclass: the registry auto-describes collectors, so a gauge whose name collides with a counter's base name (`stt_stream_sessions` vs `stt_stream_sessions_total`) is refused at registration - that is why it is `stt_stream_sessions_active`. The unlabelled `stt_pool_*` gauges describe the default model's pool and the diarizer; `stt_model_pool_size` and `stt_model_pool_available` carry every loaded model, labelled `model` and `backend`. Per-model latency is measured at the shared points, never in a route: `model_pool.acquire_model`, which every borrow of a transcription model goes through, times the wait (`stt_model_wait_seconds`) and counts the waits that ran out (`stt_model_wait_timeouts_total`), except the deep health check, which borrows with `observe=False` because its probe is no client; `metrics.measure_inference` wraps the transcriber call in `stt_server.py::transcribe_text`, `stt_server.py::run_transcription` and `stream.transcribe_piece` (`stt_model_inference_seconds`), and a new transcribing helper must wrap its call the same way. A call that raises is not timed. Those labels name the deployment's models, so they follow health's rule: with `STT_TOKENS` set, only a scrape carrying a valid token gets their series (`stt_server.py::is_scrape_detailed`); any other scrape gets the two pool gauges empty and none of the latency series, which live in `metrics.MODEL_REGISTRY` and are only rendered for such a scrape. Aggregating them under no model label for an anonymous scrape would only repeat `stt_request_seconds`.
- `GET /api/health` - `{status, pool_size, available, diarize}`, plus `diarize_pool_size` and `diarize_available` when diarization is on, plus `default_model` and `models` for a caller that passes the token check (always, while `STT_TOKENS` is empty). The top-level `pool_size` and `available` are the default model's; `models` maps every loaded id to `{backend, pool_size, available}`. `available` at 0 means every instance of that model is in flight. Open, no token required, so healthchecks keep working; the model list is configuration, like `/api/models`, so an anonymous caller does not get it. `?deep=1` runs one second of silence through every loaded model, one at a time, and reports each as ok / busy / failed: every transcription model by its id under `deep.models`, `deep.transcriber` the worst of them, `deep.diarizer` when diarization is on; 503 if any failed. It needs a token while `STT_TOKENS` is set.
- `POST /api/stt` - multipart field `file` or a raw `audio/*` body, optional `model` (query or form field, read after the upload because parsing the form consumes the raw body), optional `language` as a code (`ru`), an English name (`russian`) or `auto`. Order of checks: token (401), audio present, model (`Invalid model` / `Model not loaded`), language (`Invalid language` / `Unsupported language`), audio decodable, then the pool. The value is resolved against the backend's own table, never against a regex: a shape check passes `zz`, which then raises inside the model and surfaces as a 500, and it refuses `russian`, which the model accepts. Returns `{text, elapsed, model, language}`: the canonical id that transcribed and the language Whisper detected or used (`en` for a `.en` checkpoint, `null` for Parakeet). 400 on missing/bad audio, on a bad `model`, or on a language the chosen model does not take (without `model`, an English-only default still takes any known code and Parakeet still ignores any value), 401 without a valid token when `STT_TOKENS` is set, 413 over the size limit, 503 when the pool stays exhausted for `STT_QUEUE_TIMEOUT` (120 s by default), 500 on Whisper errors.
- `GET /api/models` - the capability catalogue: `{default, default_model, models: [...]}`, one row per loaded model (`id`, `selectable: true`, `pool_size`, `available`), one row per transcriber with nothing loaded (`selectable: false`), and the diarizer, each with its own `languages` list, `accepts_language`, and a three-valued `status` (`loaded` / `installed` / `absent`). Exactly one row has `default: true`. A row that cannot describe itself is skipped alone. Token-protected like everything except health. **Never merge the language lists into a top-level union**: Whisper knows 99 or 100 codes depending on the checkpoint, the diarizer knows none, and a union is wrong for each of them taken alone.
- `POST /api/transcript` - same body shapes and the same `model` and `language`, returns `{segments, turns, speakers, text, elapsed, model}`. Diarization runs first and its instance is **released before** a transcription model is borrowed: no request ever holds one of each, because the two pools have different sizes and different timeouts and holding both is how a deadlock starts. A segment no turn covers keeps `"speaker": null`. `overlap` marks contested speech and must stay visible in every surface that shows a transcript.
- `/api/stream` (websocket) - live transcription: a JSON `start` message (optional `model`, resolved and checked exactly like `model` on `/api/stt`, with the language then checked against that model; without `model` the language only gets the check it always got, whether it is a language at all (`backends.resolve_language_code`); `ready` names the model that serves), then raw 16 kHz mono PCM16 as binary messages, then `stop` - or `"source": "url"` and no audio, the server pulling it with ffmpeg; the server answers `ready`, a `segment` per phrase (`{id, start, end, text, speaker, overlap}`), `progress`, `skipped` (seconds dropped because the queue held more than `MAX_BACKLOG_SECONDS` of audio), and `done`. Errors are one `{"type": "error", "error", "request_id"}` and a close. A browser sends its token in the start message, other clients may use the `Authorization` header.
- `POST /api/jobs` - background processing for long recordings: same body shapes up to `JOB_MAX_CONTENT_LENGTH_MB`, `mode` = `text` | `speakers` | `turns`; 202 with the job record and a `Location`. A `text` or `speakers` job takes `model` and `language` like `/api/stt`, and its record and result name the model; one whose model a restart unloaded fails as `Model not loaded`. A `turns` job, like `/api/diarize`, reads no `model` and only checks that its language is one. `GET /api/jobs/<id>` gives `status` (`queued` with `position`, `running`, `done` with `result`, `failed` with `error`), `GET /api/jobs` lists, `DELETE /api/jobs/<id>` removes one that is not running (409 if it is). Job ids are 16 lower-case hex digits and anything else is a 404 before the disk is touched.
- `POST /api/diarize` - same body shapes, returns `{segments, speakers, elapsed}` where each segment is `{speaker, start, end}`. 503 with `Diarization disabled` when `DIARIZE_ENABLED` is false, which is the default and the only thing a CPU build ever answers.
- `POST /v1/audio/transcriptions` - OpenAI-compatible transcription, so any OpenAI SDK pointed at `/v1` works; `libs/openai_api.py` holds its options and answers, the route lives in `stt_server.py` beside `/api/stt` and shares its upload reader, `model` and `language` resolution, token, size limit, conversion (fast path included), speech gate and `STT_QUEUE_TIMEOUT` wait. Multipart with `file`; `model` is one of our ids (`whisper-1` is `Invalid model`), absent or empty means the default. `prompt` becomes Whisper's `initial_prompt` (openai-whisper keeps its last 223 tokens, first 30 s window only); Parakeet takes none and ignores it at DEBUG. A prompt holding a Whisper special token (`<|...|>`, such as `<|endoftext|>`) is a 400 `Invalid prompt` for every model: tiktoken refuses to encode one, and that would otherwise surface as a 500. The prompt is never logged, like the transcript. `temperature` must be absent or 0 (decoding is deterministic at 0 only, see above), `response_format` is `json` -> `{text}`, `text` -> a text/plain body, or `verbose_json` -> `{task, language, duration, text, segments}`; `srt`, `vtt` and `timestamp_granularities[]=word` are 400s naming their `param`. `language` in `verbose_json` is the full lower-case name Whisper reports (`libs/stt.py::get_language_name`), null for Parakeet, which reports none. Segments are Whisper's own (`segment_details` from `get_stt_result`, every field whisper gives), or for Parakeet one segment of its words with `seek` 0, `temperature` 0, `tokens` [] and the confidence fields null - never invented.
- `GET /v1/models` - `{object: "list", data: [{id, object: "model", created: 0, owned_by: <backend>}]}`, one row per loaded model by the id `/api/models` gives it. Token-protected like `/api/models`.
- Every error body is exactly `{"error": <category>, "request_id": <12 hex>}` (413 adds `limit_mb`). Details never reach the client - the full exception goes to the log under the same `request_id`. Build them with `libs/errors.py::build_error_response`, never by hand. **The one exception is every path under `/v1`**, the app-wide 401, 404, 405, 413 and 500 included: there `build_error_response` hands the same category to `build_openai_error_response`, which answers OpenAI's `{"error": {message, type, param, code, request_id}}` - `message` the category, `type` `invalid_request_error` / `authentication_error` / `server_error`, `param` the field at fault or null, `code` the category's snake_case slug - and every `/v1` response carries the request id as `X-Request-Id`. `/api/*` bodies never change shape: the web UI reads them.

## Code conventions

Beyond PEP 8 and Python 3.12 defaults:

- **File header:** `#!/usr/bin/env python3`, `# -*- coding: utf-8 -*-`, then a one-line module docstring. Every file.
- **Every function has a docstring** - nested functions, Flask handlers, Gunicorn hooks and test helpers included.
- **No name starts with `_`.** Not for "private", not for callbacks, not for unused arguments (write `exception`, not `_exception`). Dunder methods are the only exception.
- **Function names are verb + noun** (`get_pool_status`, `build_error_response`, `convert_to_wav`).
- **Imports:** stdlib, then third-party, then a `# Local imports` block, then UPPER_CASE constants. No imports buried inside functions, except the deliberate torch-after-fork ones described above.
- **Every message goes through `logging`** - never `print`. Module-level `logger = logging.getLogger(__name__)`; `libs/logs.py::setup_logging()` configures the root logger, and only entry points call it. Log calls use lazy `%`-style formatting, not f-strings.
- **Exceptions log `type(exc).__name__`, `str(exc)` and `traceback.format_exc()`**, then return a generic body.
- **Every runnable file ends with `main()` + `if __name__ == "__main__": main()`**; module-only files get an empty `main()`.
- **No decorative comment banners** (`# ----`, `# ====`).
- **Functional style over classes.** Classes only for ORM models and framework subclasses; the ones here are `libs/metrics.py::LiveGauges`, a prometheus_client `Collector`, and `stt_server.py::MemoryFormDataParser` and `stt_server.py::JobFormDataParser`, werkzeug `FormDataParser`s.
- **Do not add tests unless asked.** When behaviour changes, update the existing suite so it keeps passing.
- **A deliberately unused name is spelled `unused_something`**, never `_something`; ruff's `dummy-variable-rgx` is configured to accept exactly that prefix.
- `black` and `ruff` cover the whole repo (line length 128, target py312, rules `E,F,I,UP,B`, ignoring `E501,UP009`). Nothing is excluded except `models/`.
- **`mypy` must pass.** It runs over `libs/`, `stt_server.py`, `stt_client.py` and `gu.py` with `ignore_missing_imports`, so untyped third-party packages are fine; a real type error is not.

## Repo etiquette

- **English only** in everything that lands in the repo: code, comments, docstrings, log messages, commit messages, PR titles and bodies, README, CHANGELOG. The sole exception is `docs/README_<LANG>.md`, which are translations.
- **No em dash and no middle dot.** Use a spaced hyphen (` - `) as a separator, in prose, in UI strings and in log messages alike.
- **Branch per change**, PR into `main`. Never force-push to `main`.
- **`CHANGELOG.md` follows Keep a Changelog**; user-visible changes get an entry under `## [Unreleased]`. Release tags are a manual step, never automatic.
- **The ten `docs/README_<LANG>.md` translations mirror `README.md`.** A change to its Project structure or environment table belongs in all of them. Only three carry a translated file tree today (DE, FR, RU); the rest keep the English one.
- `.gitignore` applies a default-deny to root `*.md`: only `README.md`, `CHANGELOG.md`, `AGENTS.md` and `docs/*.md` are tracked.
